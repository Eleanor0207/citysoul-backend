2召喚流程六步驟

對應架構圖中的 ①②③④ 標號，是玩家從送出 GPS 到靈魂顯現眼前的完整體驗流程。

🔮 GPS 召喚 → AR 顯現核心流程

1
玩家手機送出目前 GPS 座標 → POST /api/v1/summon
2
Cloud Run 比對座標最接近的 Place（透過 Google Maps Places API），並向 Cloud SQL / Redis 撈取當下情境所需的 2-3 條記憶片段（檢索式記憶，非全部塞入）
3
組裝 Prompt，呼叫 Vertex AI Gemini 取得當日人格化對話內容；語音需求則另呼叫 Google Cloud TTS
4
Cloud Run 回傳：對應 Avatar 資訊 + 對話文本 + Cloud CDN 素材下載 URL
5
玩家手機端直接向 Cloud CDN 下載 Avatar 模型／動畫素材（不經過後端二次轉發）
6
本機端（ARKit/ARCore + Unity）進行 AR 渲染，靈魂顯現於玩家眼前，開始對話 / 發布任務

3API 端點目錄

依召喚流程與服務架構推導出的建議端點設計，供工程團隊參考與調整。

MethodPath用途分類
POST/api/v1/summon玩家送出 GPS，觸發靈魂召喚，回傳比對到的 Place / Avatar / 對話核心
GET/api/v1/spirits/{placeId}取得指定地標靈魂的當前人格設定與狀態核心
POST/api/v1/spirits/{placeId}/dialogue傳送玩家對話輸入，取得 LLM 生成的回應核心
GET/api/v1/spirits/{placeId}/daily-event取得該靈魂當日事件（由 Cloud Scheduler 每日排程更新）排程
GET/api/v1/quests/daily取得當前可接的每日任務列表核心
POST/api/v1/quests/{questId}/complete提交任務完成（後端狀態機判定，LLM 僅生成敘事包裝）核心
GET/api/v1/assets/{avatarId}取得 Avatar 模型／動畫素材下載 URL（經 Cloud CDN）核心
POST/api/v1/voice/tts文字轉語音請求（轉發 Google Cloud TTS）輔助
POST/api/v1/voice/stt語音轉文字請求（轉發 Google Cloud STT）輔助
