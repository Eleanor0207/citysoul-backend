# 城市靈魂 AR 遊戲 — Flutter 前端架構

> 銜接對象：《前端互動流程與感應/召喚機制》×《核心業務規則與API契約》
> 本文件是決策鏈的**第八層**：把前面定案的互動邏輯（150m感應/50m召喚、對話延續、三段式標記）
> 落地成具體的 Flutter 工程架構——畫面清單、狀態管理、路由、分層設計、服務層規劃。
> 不重複互動邏輯本身，只補「工程上怎麼組織程式碼」的部分。

## 1. 主導覽結構【已定案】

底部三分頁，對應既有mockup底部按鈕設計：

| 分頁 | 對應WBS | 說明 |
|---|---|---|
| 探索地圖（首頁） | S7 | 主要互動畫面 |
| 任務列表 | S8 | 每日任務狀態 |

相機疊圖畫面**不是分頁**，是從地圖畫面用 modal push 疊上去的獨立畫面，召喚成立後跳轉，玩家可返回地圖。

## 2. 畫面清單

| 畫面 | 對應WBS | 說明 |
|---|---|---|
| 啟動畫面 | S6 | 背景呼叫 `POST /players`（首次）或帶出既有session，無需登入UI，玩家無感 |
| 探索地圖 | S7 | OSM圖磚地圖、三段式靈魂標記、150m內嵌入對話（沿用mockup頂部搜尋列樣式）、底部當日情境卡片 |
| 相機疊圖畫面 | F4/F5/S9 | 50m觸發後跳轉，漸顯尋找靈魂、可收合對話窗（預設展開）、引導提問元件 |
| 任務列表 | S8 | 任務狀態、嘗試次數 |
| 共鳴值/Profile | S8 | 共鳴值進度、相遇收藏、記憶摘要 |

**共用元件**：對話UI（訊息列表+輸入框+引導提問）做成獨立可重用元件，同時被「探索地圖」（sense_token模式）與「相機疊圖畫面」（encounter_token模式）嵌入。因為對話延續是靠後端Redis session key（`player_id`+`spirit_id`）天然成立，前端只要維持同一個Riverpod provider狀態不重置，玩家從地圖聊到走進AR畫面，畫面上的對話串會直接接續顯示，不需要額外的「重新拉歷史」邏輯。

## 3. 技術選型【已定案】

| 項目 | 選型 | 理由 |
|---|---|---|
| 狀態管理 | **Riverpod** | 非同步(API呼叫)友善、boilerplate少、方便做token自動更新這類背景邏輯的依賴注入 |
| 路由 | **GoRouter** | Flutter官方方案，處理分頁+modal(相機畫面)疊加的返回鍵行為較乾淨 |
| 安全儲存 | `flutter_secure_storage` | 存 `install_id`、`session_token`（90天） |
| 網路層 | `dio` + 攔截器(interceptor) | 統一處理：自動帶token、sense_token快過期時靜默換發、429時轉成角色口吻的fallback文案 |
| 定位 | `geolocator` | 前景區間輪詢用，見《前端互動流程》第6節（已修正，不使用geofencing套件） |
| 角色動畫 | Rive/Lottie（既有決策） | 沿用既有決策，不重複 |

## 4. 分層架構

```
lib/
  core/        # 主題、常數、錯誤處理、共用UI元件
  services/
    token_manager.dart       # 管理三種token生命週期
    location_service.dart    # 前景區間輪詢封裝（地圖30秒／相機連續）
    api_client.dart          # dio實例+攔截器
  features/
    map/
    ar_camera/
    quest/
    profile/
    dialogue/    # 共用對話元件，被map與ar_camera嵌入
```

### 4.1 TokenManager 設計

統一調度三種token，畫面層不需要自己處理token細節：

| Token | 效期 | 換發時機 |
|---|---|---|
| Session Token | 90天 | App啟動時用舊token換新（延長效期），玩家無感 |
| Sense Token | 30分鐘 | 進入150m時核發；快過期（剩1-2分鐘）前景仍在150m內時，**靜默**重新呼叫`/sense`換發（已定案，見《前端互動流程》第2.5節），玩家UI無中斷 |
| Encounter Token | 15分鐘 | 50m召喚成立時核發，過期即該次任務嘗試失敗（不主動續期，符合既有任務逾時規則） |

### 4.2 LocationService 設計

依畫面情境切換輪詢模式（見《前端互動流程》第6節已修正內容）：

- 地圖畫面前景開啟時：每30秒查一次位置，計算與各地標距離，更新150m/50m門檻狀態（供標記視覺與召喚按鈕使用）
- 相機疊圖畫面開啟時：連續讀取位置，供漸顯視覺插值使用（僅限已在50m內、已核發encounter_token的情境）
- App切到背景或關閉地圖畫面：停止輪詢，不做背景定位（不需要背景定位權限）
