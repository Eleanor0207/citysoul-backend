## 1. 我想達到的「城市靈魂」效果（目標體驗）

### 體驗設計

玩家拿起手機：

- 🧍 城市靈魂站在街角向你揮手
- 🚶 你走近時，她會轉身看著你
- ☔ 下雨時，她會撐傘
- 🌇 黃昏時，她的服裝與光影跟著改變
- 🏛️ 經過古蹟時，她開始講述這個地方的故事

### 若目標是「震撼 Demo」

建議不要把 Pokémon GO 當作唯一標竿，而是融合三種體驗：

| 參考產品                | 提供的體驗element       |
| ----------------------- | ----------------------- |
| **Peridot**       | 角色陪伴感與環境互動    |
| **Project Astra** | AI 能理解鏡頭看到的世界 |
| **Pokémon GO**   | 定位、探索與城市事件    |

三者結合後，就是要打造的「**城市靈魂 2.0**」——一個會理解環境、記住玩家、並自然融入真實城市的 AI 數位人。

> ⚠️ **與既有 MVP 規格的落差提醒：**
>
> - 「走近時轉身看你」「經過古蹟主動講故事」「經過咖啡店主動搭話」這類**環境感知式主動互動**，目前 CONTEXT.md 定義的「首次召喚」「引導提問」機制是**玩家主動召喚 + 系統給建議提問**，不是靈魂主動偵測玩家移動路徑並搭話。若要做到這個效果，需要持續背景定位追蹤與更高頻的情境判斷，這與目前「在場紀錄：原始 GPS 座標只在驗證期間使用後即丟棄，不形成移動軌跡」的隱私原則衝突，屬於需要重新評估的方向。
> - 「服裝/光影隨天氣、時段變化」在現有規劃中屬於 2.5D 分層動畫可支援的範圍（不需要真 3D），可以先評估納入。

## 3. 我未來會加入的技術壁壘（Roadmap／差異化功能）

> 目的：讓專案不容易被複製，聚焦在以下五個系統：

1. **城市人格引擎（City Persona Engine）**
   每座城市靈魂都有可持續成長的人格、知識與語氣。
2. **多 Agent 協作（Multi-Agent Collaboration）**
   不同城市靈魂能互相討論、分工與合作完成任務。
3. **世界記憶（Persistent World Memory）**
   玩家、城市靈魂與活動都會留下可延續的共同記憶。
4. **AI 導演（Director Agent）**
   根據玩家狀態、位置、時間與天氣，動態生成劇情、任務與事件。
5. **AR 情境感知（Context-Aware AR）**
   結合定位、時間、天氣、環境與視覺資訊，讓城市靈魂真正理解眼前的世界。

> ⚠️ **與既有 MVP 規格的關係：**
> 這五項都明確標示為「未來要加入」，屬於 MVP 之後的 Roadmap，這與既有規劃「AR 升級、多 Agent 等進階功能排入 MVP 之後」的分期原則一致，不影響目前 MVP 範圍。但值得注意：
>
> - 「世界記憶」跟 CONTEXT.md 既有的「世界記憶」定義（公開歷史脈絡+每日世界變化，不含玩家輸入）不完全相同——這裡的「玩家、城市靈魂與活動都會留下可延續的共同記憶」聽起來會讓玩家互動也進入世界記憶，需要重新界定邊界，避免違反「世界記憶不包含任何玩家的輸入」這條既有原則。
> - 「多 Agent 協作」「AI 導演」都會大幅增加 LLM 呼叫次數，與既有風險排序中「🔴 高風險：AI 對話成本與延遲」直接相關，建議排入 Roadmap 時一併重新估算成本模型。
