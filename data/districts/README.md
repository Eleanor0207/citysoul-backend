# 行政區界資料

`brain.districts.boundary` 的來源資料。一個行政區一個 GeoJSON Feature。

## 為什麼要有這個目錄

`check_player_in_district()` 用 PostGIS `ST_Contains` 判斷玩家是否在區內，判斷依據**只有 `boundary` 多邊形**。`center_lat` / `center_lng` / `radius_meters` 是給地圖 UI 畫概略圓形用的，不參與判斷。

沒有 `boundary`，圍欄判斷恆為 false——區域主線的入口道具永遠發不出去，整條 arc 沒有入口。

## 資料來源

| 項目 | 內容 |
|---|---|
| 資料集 | 內政部「鄉鎮市區界線(TWD97經緯度)」 |
| 版本 | 1140318（2025-03-18） |
| 網址 | <https://data.gov.tw/dataset/7441> |
| 授權 | 政府資料開放授權條款－第 1 版 |
| 原始格式 | SHP（TOWN_MOI_1140318），UTF-8 |
| 座標系 | TWD97[2020] 地理座標 |

**沒有做座標轉換。** TWD97[2020] 與 WGS84 / EPSG:4326 的差異在公分等級，對半徑動輒數百公尺的圍欄判斷沒有意義，硬轉一次反而多一個出錯的環節。

## 檔案

| 檔案 | 區 | 頂點數 |
|---|---|---|
| `wanhua.geojson` | 萬華區（`district_id = wanhua`） | 759 |

外環依 RFC 7946 轉成逆時針（shapefile 原本是順時針）。

## 已驗證

用本機 PostGIS 跑過：

```text
ST_IsValid          True
ST_Area             7.47 km²
龍山寺召喚點          內
西門紅樓             內
剝皮寮              內
台北 101 / 故宮      外
```

## ⚠️ 面積跟官方統計對不上，這是正常的

實測 7.47 km²，內政部統計的萬華區面積是 8.85 km²，差 1.39 km²。

不是資料錯誤。把臺北市 12 個區全部量一遍就看得出規律：

```text
沿河的區偏小   萬華 -1.39   大同 -0.89   松山 -0.63
其他區偏大     北投 +0.91   內湖 +0.37   中山 +0.36
合計          269.88 vs 271.80（差 0.7%）
```

總量幾乎一致，差異是**河道面積在各區之間的歸屬不同**——界線圖把河道畫在堤防線上，面積統計則把河面計入沿河各區。

**對我們沒有影響，甚至比較好**：玩家站在淡水河面上這件事不會發生。實測河濱公園（華江、華中）與青年公園都在區內，只有橋樑中段落在區外。

## 一個要留意的邊界

西門捷運站距離區界只有 **15 公尺**——那裡是萬華與中正的交界。GPS 誤差輕易超過 15 公尺，所以站在西門站附近的玩家可能被判定成不在萬華區。

這不影響「阿明的遺願」（三個地標的召喚點距邊界都在 400 公尺以上），但之後若有劇情要在西門站觸發，不能依賴這個圍欄。

## 怎麼重新產生

不需要定期更新——行政區界很少變動。真要重產時：

1. 從上表的網址下載 SHP zip 並解壓
2. 用任何能讀 shapefile 的工具（`pyshp`、GDAL、QGIS）取出 `COUNTYNAME = 臺北市` 且 `TOWNNAME` 為目標區的那一筆
3. 外環反轉成逆時針，座標保留 7 位小數
4. 用 PostGIS 驗 `ST_IsValid`，並確認該區的靈魂召喚點都判定為內部

轉檔工具**刻意不列進 `requirements.txt`**：這是一次性的資料處理，不是執行期相依。產出的 GeoJSON 已經進版控，正常情況下沒有人需要再跑一次。
